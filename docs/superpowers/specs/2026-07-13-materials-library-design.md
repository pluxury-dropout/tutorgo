# Библиотека материалов + синхронный плеер на доске

**Дата:** 2026-07-13
**Статус:** утверждён, готов к планированию

## Задача

Препод заливает медиа и другие файлы в личное хранилище, а во время урока запускает
их с доски так, чтобы звук/видео шли у обоих участников одновременно: play, pause и
перемотка применяются к обоим.

## Решения по скоупу

| Вопрос | Решение |
|---|---|
| Привязка к курсу/уроку | Нет. Плоское личное хранилище препода, он сам решает, что запускать |
| Где живёт UI | Сайд-панель внутри доски Excalidraw, кнопка — под нативной кнопкой библиотеки |
| Кто видит библиотеку | Только препод (`!isGuest`) |
| Кто управляет плеером | Оба: препод и ученик могут жать play/pause/seek |
| Типы файлов | Любые. Медиа → плеер, картинка/PDF → на доску, прочее → скачивание |
| Размер файла | До 50 МБ — существующий лимит, не меняем |
| Доступ ученику вне звонка | Вне скоупа. Отдельная фича со своей моделью прав |

Не делаем: переименование, перемещение между папками, транскодирование, превью, поиск.

## Канал синхронизации: WS доски, не LiveKit

Плеер живёт в доске, поэтому синхронизируем через существующий WS доски
(`handlers/whiteboard_ws.go`), а не через LiveKit data channel.

Причины:

1. В `wbHub.run()` в `switch parsed.Type` есть ветка `default: relay verbatim` — новый
   тип сообщения ретранслируется всем, кроме отправителя, **без правок сервера**.
2. Доску открывают и без звонка (роут `/boards/[courseId]`, гостевой вход по инвайту).
   LiveKit там недоступен.
3. Не надо прокидывать LiveKit-контекст в компоненты доски.

## Схема БД

Миграция `025_materials.sql`. Adjacency list: папка — строка без `file_path`.

```sql
CREATE TABLE materials (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  tutor_id   UUID NOT NULL REFERENCES tutors(id) ON DELETE CASCADE,
  parent_id  UUID REFERENCES materials(id) ON DELETE CASCADE,  -- NULL = корень
  kind       TEXT NOT NULL CHECK (kind IN ('folder','file')),
  name       TEXT NOT NULL,
  file_path  TEXT,          -- ключ объекта в S3; NULL у папок
  mime_type  TEXT,
  size_bytes INT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK (kind = 'folder' OR file_path IS NOT NULL)
);
CREATE INDEX idx_materials_tutor_parent ON materials(tutor_id, parent_id);
```

Ключи в S3: `materials/<uuid><ext>` — рядом с существующим `board-assets/`.

## API

Все роуты под `middleware.Auth`, скоуп по `tutorID` из контекста.

| Метод | Роут | Тело / параметры | Ответ |
|---|---|---|---|
| GET | `/materials` | `?parent_id=` (пусто = корень) | `[]MaterialResponse`, папки первыми, затем по `name` |
| POST | `/materials/folder` | `{name, parent_id?}` | 201, `MaterialResponse` |
| POST | `/materials` | multipart: `file`, `parent_id?` | 201, `MaterialResponse` |
| DELETE | `/materials/:id` | — | 204 |
| GET | `/materials/:id/url` | — | 302 на presigned-ссылку, TTL 4 часа |

`MaterialResponse`: `{id, kind, name, mime_type, size_bytes, created_at}`.

Правила:

- `parent_id` при создании обязан принадлежать тому же преподу и быть `kind='folder'`,
  иначе 400.
- Загрузка файла повторяет `WhiteboardHandler.UploadAsset`: `store.Put` → запись в БД,
  при ошибке записи — `store.Remove` (откат осиротевшего объекта).
- `DELETE` файла удаляет объект в S3 после удаления строки. Непустую папку удалить
  нельзя → 409 (тот же паттерн, что «курс с уроками не удаляется»).
- TTL 4 часа: ссылка должна пережить весь урок. У `board-assets` TTL 20 минут — там
  картинка перезапрашивается по редиректу, а тут ссылку получает ученик по WS и
  переполучить её не может.

## Синхронный плеер

Новый тип WS-сообщения, обрабатывается только на клиенте:

```jsonc
{
  "type": "media",
  "payload": {
    "action": "open" | "play" | "pause" | "seek" | "close",
    "url": "<presigned>",   // только в open
    "mimeType": "audio/mpeg",
    "name": "unit3.mp3",
    "position": 12.4        // секунды, в play/pause/seek/open
  }
}
```

Мастера нет, оба участника равноправны — как при рисовании. `wbHub.broadcast` — канал,
разбираемый одной горутиной, поэтому порядок событий одинаков у всех клиентов;
побеждает последнее сообщение. Синхронизация часов не делается: дрифт 100–300 мс для
аудирования незаметен.

Приём `media` применяется к локальному `<audio>`/`<video>` напрямую и **не** порождает
исходящее сообщение (иначе эхо-петля). Флаг «применяю удалённое событие» глушит
локальные обработчики `onPlay`/`onPause`/`onSeeked` на время применения.

**Late-join.** Клиент, подключившийся позже, шлёт `{"type":"media_req"}`; тот, у кого
плеер открыт, отвечает `media/open` со своей текущей позицией. Сервер снова не трогаем.
Если открыто ни у кого — ответа нет, и это нормально.

**Автоплей.** `play()` у ученика будет отклонён браузером, если тот ещё не
взаимодействовал со страницей. Reject ловим и показываем кнопку «Включить звук»; по
клику проигрывание стартует с присланной позиции.

## Frontend

Новые файлы в `frontend/src/components/whiteboard/`:

- `MaterialsPanel.tsx` — сайд-панель: хлебные крошки, папки, файлы, загрузка, удаление,
  создание папки.
- `MediaPlayer.tsx` — плавающий плеер поверх доски, виден обоим.

Правки:

- `useExcalidrawSync.ts` — `sendMedia(payload)` и колбэк `onMedia(payload)`; ответ на
  `media_req`; отправка `media_req` при подключении. Ровно тот же приём, что у
  существующего `{type:'file'}` (`useExcalidrawSync.ts:444`).
- `ExcalidrawCanvas.tsx` — кнопка «Материалы» в `renderTopRightUI` рядом с кнопкой
  картинки (гейт `!isGuest`), рендер панели и плеера.
- `frontend/src/types` + api-клиент — типы и вызовы `/materials`.

Клик по файлу в панели:

| Тип | Действие |
|---|---|
| `audio/*`, `video/*` | получить presigned-URL → `sendMedia({action:'open'})` → плеер у обоих |
| `image/*` | вставка на доску существующим путём (S3-ссылка + сообщение `file`) |
| `application/pdf` | скачать Blob → существующая конвертация pdfjs → `PdfRangeDialog` |
| прочее | скачивание по presigned-ссылке |

Визуальный дизайн панели и плеера дорабатывается отдельно; здесь фиксируется только
структура и поведение.
