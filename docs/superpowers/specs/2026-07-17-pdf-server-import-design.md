# Серверный импорт PDF на доску

**Дата:** 2026-07-17
**Статус:** дизайн утверждён, ждёт имплементации

## Проблема

Сейчас PDF рендерится в браузере преподавателя (pdf.js) и каждая страница
заливается в S3 отдельным запросом. 50 страниц = 50 точек отказа на wifi
преподавателя; упавшие страницы оставляют дыры в документе, вся работа умирает
вместе с закрытой вкладкой. Требование: 100% страниц доезжают до доски, как в
Miro.

Как это устроено у Miro (наблюдаемый контракт): файл уходит на сервер одним
запросом, конвертирует серверная джоба с ретраями, страницы проявляются по
готовности. Единица отказа — документ целиком с повтором до успеха, а не
отдельная страница.

## Решения, принятые с пользователем

- Импортирует **только преподаватель** (авторизованный роут, tutor JWT).
  Гостевой путь не нужен, лимитер гостей не трогаем.
- Лимит — существующие **50 МБ на файл**, лимита страниц нет (как у Miro).
  Диапазон страниц из диалога уезжает на сервер — рендерятся только они.
- Клиентский рендер **удаляется полностью** (pdfjs-dist из бандла, lib/pdf.ts,
  рендер-пул в ExcalidrawCanvas). Один путь — одно поведение.
- Очередь — **подход C**: отдельный воркер. Технология — **River**
  (Postgres-backed): очередь живёт в той же БД, enqueue транзакционен с записью
  импорта, ретраи/backoff/восстановление после рестарта из коробки. Рост =
  больше воркер-контейнеров, код не меняется.

## Архитектура

Один Docker-образ, две роли по env (`ROLE=api` / `ROLE=worker`):

```
клиент ──POST /boards/:id/pdf──────▶ API ──S3──▶ оригинал PDF
клиент ◀─{import_id, num_pages, sizes}─┘   └─▶ board_pdf_imports (pending)

клиент ──POST /pdf-imports/:id/start {from,to}──▶ API
        ◀─{pages:[{file_id,url,w,h}]}── (tx: board_assets + pages + river_job)

worker ── берёт джобу ── S3 GET оригинал ── pdftoppm -jpeg -r 200
       └─ per-page: S3 PUT ── pg_notify('board_events', {type:'file',...})

API ── LISTEN board_events ──▶ WS-хаб страницы ──▶ все клиенты (hydrateFiles)
```

- `pdftoppm` из poppler-utils (`apk add` в образ): шелл-аут, без cgo, переживает
  битые PDF лучше Go-библиотек (go-fitz = cgo + AGPL MuPDF).
- `pdfinfo` в preflight отдаёт число страниц и габариты каждой (у страниц PDF
  бывают разные размеры).
- Растр: JPEG q85, 200 DPI (A4 → ~1700×2340). Страницы PDF непрозрачны — альфа
  не нужна, JPEG в разы легче PNG. Плотность ~1.85× от места на доске
  (LAYOUT_SCALE 1.5 остаётся на клиенте) — запас на зум.
- События воркер→API через `pg_notify`: воркер — отдельный процесс, у него нет
  доступа к in-process WS-хабам. Бонус: при нескольких API-инстансах каждый
  услышит NOTIFY и раздаст своим клиентам.

## Поток данных

1. **Drop PDF** → клиент сразу шлёт multipart на `POST /boards/:boardId/pdf`.
   API: валидация 50 МБ → `pdfinfo` по temp-файлу → S3 PUT оригинала
   (`board-pdf/{uuid}.pdf`) → insert `board_pdf_imports` (status=pending) →
   ответ `{import_id, num_pages, page_sizes}`.
2. **Диалог диапазона** (существующий `PdfRangeDialog`) показывается с
   `num_pages` из ответа — заливка проходит, пока преподаватель выбирает.
3. **Подтверждение** → `POST /pdf-imports/:id/start {from, to}`. Одна
   транзакция: N записей `board_assets` (ID = будущие fileId), `pages` jsonb,
   `river.InsertTx`. Ответ — `{pages: [{file_id, url, w, h}]}`.
4. **Клиент** раскладывает pending-элементы `layoutPages` (7 в строке, перенос
   строк — уже реализовано и покрыто тестами) и регистрирует `fileId → url` в
   files-карте (`registerFile`): раскладка и указатели уезжают пирам и в
   снапшот сразу — импорт переживает закрытие вкладки инициатора.
5. **Воркер**: скачивает оригинал, рендерит диапазон, per-page S3 PUT под
   заранее известный ключ → отметка `done` в `pages` → `pg_notify`
   `{page_id, type:'file', fileId, url, mimeType}`. Все страницы готовы →
   status=done.
6. **API** пересылает событие в хаб — существующий WS-тип `file`,
   `hydrateFiles` у клиентов подтягивает картинку в плейсхолдер. Новых
   клиентских механизмов для happy path нет.
7. **Прогресс-тост** у инициатора — счётчик `file`-сообщений по своим fileId.

## Схема данных

```
board_pdf_imports
  id           uuid PK
  board_id     uuid → whiteboards
  page_id      uuid          -- страница доски для WS-событий
  tutor_id     uuid          -- владелец, проверка доступа
  s3_key       text          -- оригинал PDF
  status       text          -- pending | rendering | done | failed
  pages        jsonb         -- [{n, asset_id, w, h, done}]
  error        text NULL
  created_at / updated_at
```

`pages` — jsonb, не таблица: страницы читаются/пишутся только вместе с
импортом. Assets — обычные `board_assets`, раздаёт существующий `ServeAsset`.
Плюс штатные миграции River (`river_job`), через тот же goose.

## Обработка отказов

- **Транзиентный сбой** (S3, OOM, рестарт): River повторяет джобу с backoff,
  до 5 попыток. Джоба идемпотентна: страницы с `done=true` пропускаются,
  S3-ключи известны заранее.
- **Постоянный отказ** (битый файл, попытки исчерпаны): status=failed,
  `pg_notify` типа `import_failed` со списком fileIds → API в хаб → клиенты
  удаляют плейсхолдеры этих fileIds (единственный новый WS-тип в дизайне),
  инициатору — тост с ошибкой. Битая отдельная страница — не сценарий:
  `pdftoppm` на ней отдаёт пустой лист, а не ошибку.
- **Preflight-мусор** (дропнул и закрыл диалог): воркер при старте и раз в
  сутки удаляет импорты pending старше 24ч вместе с S3-оригиналом (паттерн
  горутины автозавершения уроков из main.go).
- Оригинал PDF после успеха **хранится** (дёшево; позволяет чинить/перерендить).
  ponytail: чистку оригиналов добавить, когда S3 станет заметен в счёте.

## Изменения на клиенте

Удаляется: `pdfjs-dist` (−400 КБ бандла), `src/lib/pdf.ts`, PDF-ветка
`handlePdfConfirm` (рендер-пул, webp-кодирование, воркеры).

Остаётся: `PdfRangeDialog` (numPages — из preflight-ответа), `layoutPages` +
тесты, pending-элементы, `withRetry` для одиночных картинок.

Новое: два вызова API (preflight, start), обработчик WS `import_failed`
(удалить элементы по fileIds), прогресс-тост по `file`-сообщениям.

## Тестирование

- **Go, сервис** (`package service_test`, testify/mock — существующий паттерн):
  preflight (валидация, создание записи), start (транзакция, диапазон),
  идемпотентность повтора джобы (done-страницы пропущены), чистка pending.
- **Парсер `pdfinfo`** — чистая функция, юнит-тесты на реальном выводе.
- **Рендерер** за узким интерфейсом (`RenderPages(ctx, src, from, to) →
  []Page`); в тестах джобы — фейк. Реальный `pdftoppm` — smoke-тест по образцу
  `storage/smoke_test.go` (скипается без бинаря).
- **Frontend**: `layoutPages` уже покрыт; API-обёртка тривиальна, без тестов.

## Вне скоупа

- Ленивая догрузка/тайлинг картинок на клиенте (память Excalidraw при сотнях
  страниц) — отдельная тема.
- Компакция tombstones снапшота (carry-forward из миграции на Excalidraw).
- Импорт PDF учениками.
