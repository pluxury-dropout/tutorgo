# Кнопка следующего урока в сайдбаре + вкладка «Пробный урок» с общей доской

**Дата:** 2026-07-14
**Статус:** согласовано

## Задача

Кнопка внизу сайдбара сейчас открывает безымянную быструю комнату (`callsApi.startQuickRoom`)
и висит там всегда — постоянный зелёный пульсирующий индикатор, который ничего не значит.

Нужно:

1. Кнопка стартует **следующий урок по расписанию**, а не безымянную комнату.
2. Кнопки нет, пока до урока больше 10 минут, — сайдбар не мигает в неурочное время.
3. Над кнопкой — название курса, чтобы препод видел, куда именно заходит.
4. Безымянные комнаты остаются, но переезжают в отдельную вкладку **«Пробный урок»**:
   это созвон с учеником, которого ещё нет в базе, урок не пишется в курс.
5. У всех пробных уроков — **одна общая доска** на препода.

## Решения по скоупу

| Решение | Почему |
|---|---|
| Окно показа кнопки — `[start − 10 мин, start + duration_minutes]` | Препод опоздал или перезагрузил вкладку посреди урока — кнопка на месте. После конца урока исчезает. |
| Ничего, если урока в окне нет | Явное требование: не грузить визуал в ненужное время. |
| Пробный урок — отдельная вкладка, не fallback-состояние кнопки | Пробные нужны редко; смешивать их с расписанием в одном слоте — путать два разных действия. |
| Одна пробная доска на препода, содержимое сохраняется между уроками | Просьба пользователя. Заготовки для пробных занятий (типовые задания) переиспользуются. |
| Кнопки «Очистить доску» нет | Страницы доски уже добавляются и удаляются вручную. |

## Что уже есть (менять не нужно)

- `useCalendar(from, to)` в сайдбаре отдаёт `CalendarLesson[]` с полями `subject` (название курса),
  `scheduled_at`, `duration_minutes`, `status`, `is_group`, `student_name`.
- Страница `/lessons/[id]/call` сама выполняет весь протокол старта: `callsApi.startRoom(id)` →
  `getRoomToken(id)` → LiveKit. Сайдбару нужно знать только **id урока**.
- Быстрая комната целиком: `POST /calls/quick`, страница `/room/[id]`, гостевой вход `/join/room/[id]`.
- Гостевая половина доски: гость получает invite-токен через LiveKit DataChannel
  (`board-open` → `whiteboardApi.joinByInvite`) и про курсы ничего не знает.

## Выбор урока

Чистая функция в новом файле `frontend/src/components/layout/nextLesson.ts`:

```ts
export function pickActiveLesson(
  lessons: CalendarLesson[],
  now: Date,
  leadMinutes = 10,
): CalendarLesson | null
```

Правила:

- только `status === 'scheduled'`;
- урок попадает в окно, если `start − leadMinutes ≤ now ≤ start + duration_minutes`;
- из подходящих — ближайший по `scheduled_at`;
- иначе `null`.

Функция чистая и без DOM — тестируется `node:test` (как `mediaSync.test.ts`).
Граничные случаи в тестах: ровно `−10:00`, ровно конец урока, два урока подряд,
`cancelled`/`completed` игнорируются, пустой список.

## Сайдбар

**Данные.** `useCalendar` в `CalendarSidebarPanel` сейчас запрашивает ровно сегодняшние сутки.
В 23:55 урок на 00:05 в диапазон не попадёт и кнопка не появится — расширяем `to` на сутки
вперёд. `TodayList` фильтрует по `isSameLocalDay`, поэтому его вид не меняется.

**Тикер.** `now` вычисляется один раз при монтировании: без обновления кнопка не появится сама
(вкладка открыта в 09:45, урок в 10:00). Добавляем `setInterval` на 30 секунд, обновляющий `now`
в state.

**Вид.** Слот внизу сайдбара:

- **урок в окне, ещё не начался** — строка `{subject}` + время старта мелким шрифтом, под ней
  кнопка «Начать урок» с зелёной пульсирующей точкой (текущий стиль). Клик →
  `router.push('/lessons/{id}/call')`;
- **урок в окне и уже идёт** (`now ≥ start`) — та же карточка, надпись «Присоединиться»;
- **урока в окне нет** — слот пуст.

**Навигация.** В массив `NAV` добавляется пункт «Пробный урок» → `/trial`.

## Страница `/trial`

Карточка в существующем формате (`SectionCard`) с одной кнопкой «Начать пробный урок»:
`callsApi.startQuickRoom()` → `sessionStorage.setItem('quick-room-{id}', …)` →
`router.push('/room/{id}')` — ровно то, что делает сегодняшняя кнопка сайдбара.
Ссылку для ученика препод копирует внутри комнаты (кнопка там уже есть).

Короткая поясняющая строка: пробный урок не привязан к курсу и не попадает в расписание,
доска у всех пробных общая.

## Пробная доска

Доска сегодня привязана к курсу: `boards.course_id UUID NOT NULL REFERENCES courses(id)`,
`UNIQUE(course_id)`. Поэтому в быстрой комнате доски нет вообще — `/room/[id]` не передаёт
`courseId` в `CallRoom`.

**Миграция `026_trial_board.sql`:**

```sql
-- +goose Up
ALTER TABLE boards ALTER COLUMN course_id DROP NOT NULL;
CREATE UNIQUE INDEX idx_boards_trial ON boards (tutor_id) WHERE course_id IS NULL;

-- +goose Down
DROP INDEX idx_boards_trial;
DELETE FROM boards WHERE course_id IS NULL;
ALTER TABLE boards ALTER COLUMN course_id SET NOT NULL;
```

Частичный уникальный индекс — это и есть инвариант «ровно одна пробная доска у препода»,
и держит его БД, а не сервис.

**Репозиторий / сервис:** `GetOrCreateTrialBoard(ctx, tutorID)` — тот же upsert и то же
создание первой страницы («Страница 1»), что в `GetOrCreateBoard`, но без
`CourseBelongsToTutor`: курса нет, проверять нечего. Владение проверяется по `tutor_id`
самой доски.

**Роут:** `auth.GET("/boards/trial", whiteboardHandler.GetTrialBoard)` — в той же группе,
что остальные board-роуты (`Auth` + `RequireActiveSubscription`). Ответ — `BoardWithPages`,
как у `GetBoardByCourse`.

**Фронт:** `CallRoom` получает проп `trial?: boolean`. Места, где сейчас стоит гейт `!courseId`
(автооткрытие доски после подключения, `handleToggle`), переходят на «нет ни курса, ни trial».
Источник доски: `trial ? whiteboardApi.getTrialBoard() : whiteboardApi.getBoardByCourse(courseId)`.
`courseId` продолжает передаваться в `ExcalidrawCanvas` только для курсовых уроков — домашка
у пробного урока отсутствует по определению.

Страница `/room/[id]` передаёт `trial` для роли препода. Гостевой путь не меняется.

## Что осталось за бортом

| Пропущено | Когда добавлять |
|---|---|
| Кнопка «Очистить пробную доску» | Если препод попросит: страницы и так удаляются вручную. |
| Отдельная доска на каждый пробный урок | Явно не нужно — пользователь хочет одну. |
| Показ следующего урока, если до него больше 10 минут (обратный отсчёт) | Если препод скажет, что не хватает контекста. |
| Пробный урок → создание ученика/курса в один клик | Отдельная фича, другая модель данных. |
