## Ключевое уточнение про Kaspi

Под «Kaspi» скрываются две разные вещи:

1. **Kaspi Gold — это карта** (Mastercard, 16 цифр). Принимается **любым**
   card-эквайером как обычный Mastercard, токенизируется, автосписание
   работает. Большинство «привязок Kaspi к сервисам» — это именно ввод номера
   этой карты.
2. **Кнопка «Оплатить через Kaspi» / Kaspi QR** — редирект в приложение Kaspi,
   оплата со счёта без ввода карты. Не токенизируется (нельзя тихо автосписывать),
   есть не у всех эквайеров.

**Вывод:** раз приём карт сам по себе закрывает Kaspi Gold, отдельная
интеграция «кнопки Kaspi» **не обязательна** — это бустер конверсии для тех,
кто не хочет вбивать номер карты. YAGNI → в v2 или никогда. Автопродление по
Kaspi Gold работает штатно, потому что это карта.

## Сравнение провайдеров (KZ)

| Провайдер | Recurring | Kaspi Gold (карта) | Кнопка Kaspi | Примечание |
|---|---|---|---|---|
| **Freedom Pay** (ex-PayBox.money) | ✅ | ✅ | ✅ | Локальный, Freedom Holding, KZT, ИП. Дефолт. |
| **CloudPayments KZ** | ✅✅ | ✅ | ✗ | Сильный recurring-API, СНГ-охват; «российский» флёр. |
| **Halyk ePay** | ✅ | ✅ | частично | Крупнейший банк-эквайер, но API бюрократичнее. |
| **Kaspi Pay / QR** | ✗ (слабо) | — | ✅✅ | Король розницы KZ, но рекурренты костыльные. Не как основной. |
| **Robokassa** | ✅ | ✅ | частично | СНГ-агрегатор, проще, менее премиальный. |
| **Stripe / Paddle / Lemon Squeezy** | ✅✅ | — | ✗ | ❌ не принимают продавцов из KZ — мимо. |

## Решение

**Провайдер — Freedom Pay** (локальный KZ, KZT, работает с ИП, принимает и
карты, и кнопку Kaspi, умеет рекурренты). CloudPayments — запасной вариант,
разница сузилась до тарифов/вкуса, т.к. спец-интеграция Kaspi не нужна и СНГ
сейчас не требуется.

Финально подтвердить тарифы/комиссии Freedom Pay vs CloudPayments перед
подключением.

## Токенизация (что это и зачем)

Чтобы автопродлить подписку, надо повторно списать с карты, когда пользователя
нет на сайте. Хранить номер карты + CVV у себя **нельзя** (PCI DSS; CVV хранить
запрещено вообще). Решение: при первой оплате карта вводится **на стороне
провайдера**, он возвращает **токен** (`tok_...`) — строку, бесполезную для
кражи, работающую только через API этого провайдера для нашего мерчанта.
Автосписание = `provider.Charge(token, amount)`.

Аналогия из нашей же кодовой базы: токен карты — как наши refresh/JWT токены.
Не храним секрет (пароль/карту), храним отзываемое право действовать от имени
пользователя, привязанное к одному потребителю.

Цена токенизации в коде — новые ветки, которых нет при разовой оплате:
списание упало (нет денег) → ретрай/блок?; карта истекла → перепривязать;
отмена автопродления/отвязка карты; идемпотентность (не списать дважды на
повторный webhook).

## Развилка объёма v1 (НЕ РЕШЕНА — спросить владельца)

- **v1a (лениво):** hosted-страница Freedom Pay (редирект → карта или Kaspi),
  webhook подтверждает → активируем период. Продление **ручное** (напоминание +
  ссылка за N дней до конца). Без хранения карт, без PCI, минимум состояний.
  Токенизация — в v2. Быстрее до прибыли.
- **v1b:** сразу токенизация + автосписание карт. Больше кода и состояний,
  зато retention с первого дня.

Рекомендация автора: начать с **v1a**. Автопродление — оптимизация retention,
отложимо; главное сейчас — закрыть дыру `confirm` и начать принимать деньги.

## Скелет v1a (ложится на существующий код)

```
Checkout → создать платёж в Freedom Pay, вернуть URL их hosted-страницы
           (редирект пользователя туда; там карта или Kaspi)
POST /subscription/webhook → проверить подпись Freedom Pay
           (образец HMAC-проверки уже есть — livekit webhook)
           → repo.Activate(tutorID, plan, period_end)
удалить открытый POST /subscription/confirm   ← закрывает дыру
```

Оба эндпоинта (`/subscription`, `/subscription/checkout`, `/subscription/webhook`)
должны остаться ВНЕ гейта `RequireActiveSubscription`, иначе заблокированный
не сможет оплатить.
