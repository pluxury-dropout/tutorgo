# Вкладка «Ученики» на странице курсов

**Дата:** 2026-07-09
**Статус:** согласован дизайн

## Проблема

Вкладка «Ученики» в сайдбаре — это отдельная страница `/students`, которая
показывает только список учеников и больше ничего. Отдельный top-level пункт
навигации ради одного списка избыточен. Консолидируем: список учеников
становится вкладкой на странице курсов, между «Активные» и «Архив».

## Итоговая навигация

Страница курсов (`/courses`), вкладки: **Активные · Ученики · Архив**.

Пункт «Ученики» убирается из сайдбара и мобильной нижней навигации.
Карточка ученика `/students/[id]` не трогается — меняется только точка входа
в *список*.

## Архитектурные решения

### 1. Изоляция: `StudentsList` — презентационный компонент

Новый `components/students/StudentsList.tsx` рендерит только строки списка
(`SectionCard` + строки, ~55 строк, переносятся почти дословно из текущего
`students/page.tsx`). Props:

```ts
{
  students: Student[]
  onEdit: (s: Student) => void
  onDelete: (s: Student) => void
}
```

Клик по строке → `router.push('/students/${id}')` внутри компонента.

Оркестрацию (данные, поиск, пагинация, форма, счётчик) держит страница
курсов. Причина — динамический заголовок (см. п. 2) должен показывать
отфильтрованный счётчик, который приходит из того же `useStudentsPaged`, что
и список; поэтому источник данных живёт на уровне страницы.

### 2. Динамический заголовок

`PageHeader` на странице курсов меняет `title` / `meta` / `actions` в
зависимости от активной вкладки:

| Вкладка   | title    | meta                  | actions               |
|-----------|----------|-----------------------|-----------------------|
| active    | Курсы    | N курсов              | Добавить курс         |
| students  | Ученики  | N учеников (фильтр.)  | Добавить ученика      |
| archive   | Курсы    | (как сейчас)          | —                     |

`N учеников` берётся из `useStudentsPaged({ search: studentSearch }).total` —
отражает текущий поиск.

### 3. Состояние вкладки → в URL, поиск учеников → локально

- Активная вкладка: `?tab=students` в URL. Инициализируем `tab` из
  `searchParams`, при клике обновляем query (shallow `router.replace`).
  Нужно, чтобы редирект со старого `/students` и deep-link попадали на
  нужную вкладку, а не на «Активные».
- Поиск и страница учеников: **локальный стейт** (`studentSearch`,
  `studentPage`), а НЕ URL. Иначе конфликт с URL-параметрами `?search=&page=`,
  которые уже используют активные курсы.

Единое поле поиска под вкладками переключает источник: на вкладке курсов
пишет в URL (как сейчас), на вкладке учеников — в `studentSearch`.

### 4. Старый роут `/students`

`students/page.tsx` → server component с одной строкой:
`redirect('/courses?tab=students')`. Нужен только для закладок и кнопки
«назад» — внутри приложения ссылок на список учеников не остаётся.

## Затрагиваемые файлы

- `components/students/StudentsList.tsx` — **новый** (презентационный список).
- `app/(dashboard)/courses/page.tsx` — третья вкладка, динамический заголовок,
  студенческие хуки/стейт/форма, переключение источника поиска.
- `app/(dashboard)/students/page.tsx` — заменить на `redirect`.
- `components/layout/Sidebar.tsx` — убрать пункт «Ученики».
- `components/layout/MobileBottomNav.tsx` — убрать пункт «Ученики».

## Вне scope (YAGNI)

- Поиск учеников в URL — не нужен, deep-link на конкретный поисковый запрос
  учеников ценности не даёт.
- Общий «хаб»-нейминг страницы — заголовок динамический, этого достаточно.
- Рефактор карточки ученика `/students/[id]` и формы `StudentForm`.

## Проверка

- Переход по трём вкладкам: заголовок/метрика/кнопка меняются корректно.
- Поиск на вкладке учеников не ломает URL активных курсов и наоборот.
- Открытие `/students` редиректит на вкладку «Ученики».
- Создание/редактирование/удаление ученика работает из новой вкладки.
- В сайдбаре и мобильной навигации пункта «Ученики» больше нет; список
  доступен только через вкладку.
