Как хранить состояние быстрой комнаты?

Нажми кнопку → создаётся новая одноразовая комната → копируешь ссылку → отправляешь ученику

A

In-memory map на Go-сервере

Состояние комнат живёт в памяти сервера (Go map + mutex). Нет миграций, нет новых таблиц. Комнаты сбрасываются при перезапуске сервера — для одноразовых сессий это нормально.

Плюсы

  • Нет миграций
  • Минимум кода
  • Мгновенная проверка статуса

Минусы

  • Сброс при рестарте
  • Нет истории звонков

✓ Рекомендую — идеально для одноразовых комнат

B

Новая таблица quick_rooms в БД

Миграция добавляет таблицу quick_rooms(id, tutor_id, started_at, ended_at). Полный трекинг истории. Структура идентична текущим room-полям в таблице lessons.

Плюсы

  • История всех звонков
  • Переживает рестарт
  • Консистентно с кодом

Минусы

  • Нужна миграция
  • Больше кода
C

LiveKit как источник правды

Не хранить состояние вообще. Статус комнаты проверяется через LiveKit API (ListRooms). Токены генерируются напрямую по UUID без записи в БД или память.

Плюсы

  • Нет локального стейта
  • LiveKit — единый источник

Минусы

  • Зависимость от LiveKit API
  • Медленнее (сетевой запрос)
  • Любой знающий UUID — войдёт
